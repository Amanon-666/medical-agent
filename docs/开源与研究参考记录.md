# 开源与研究参考记录

## 记录规则

- **直接依赖**：运行时实际安装并调用的软件包。
- **API 接入**：仅通过公开接口调用外部服务，不复制其实现代码。
- **数据来源**：用于构建、验证或评测的数据集。
- **方法参考**：用于确定指标、接口或架构，不复制源码。
- **待选型**：已进入设计比较，但尚未成为当前实现。

如引入或修改外部代码，必须补充具体版本、文件范围、许可证和修改说明。

## 当前任务三实现的来源边界

任务三的语义层、只读 SQL 安全校验、分析记录、图表数据契约和报告导出为项目内实现：

- 数据库访问使用 Python 标准库 `sqlite3` 的只读能力；
- 当前网页统计图使用项目自有 SVG 渲染器，支持条形图、柱状图、
  环形图和折线图；
- 导出报告使用项目自有 HTML、CSS、CSV 和 JSON 生成逻辑；
- 当前实现没有复制 Apache ECharts、Vega-Lite、Spider 或 BIRD 的源码。

图表选择策略参考 Vega-Lite 的“数据字段与视觉编码匹配”思路，
但图表契约、选择规则和渲染代码均为项目内实现。下列项目没有成为
运行时依赖，不能描述为已集成组件。

## 本轮离线关系规则与级联路由优化

- 本轮仍只使用项目现有的 CBLUE 词典、关系词表和知识图谱资产，未引入外部代码、模型或新的数据来源。
- 离线后端与 hybrid 首轮统一使用同一套实体、关系和候选路由逻辑：否定判断提前于已知关系匹配；关系使用实体实际位置；普通“在”不再直接触发发病部位；诊断上下文不再跨句补关系。
- hybrid 的内部路由使用原始离线候选，但最终落地仍执行质量门禁：中可靠候选按“明确拒绝才删除”处理；低可靠实体继续过滤，只有带有关系触发证据的低可靠关系才进入定向复核，LLM 明确接受后提升为已复核事实；缺口句仍交给 LLM 查缺补漏，候选在复核前按语义去重。
- 针对 CMeIE 中 `疾病@后续描述` 的数据格式，级联缺口识别会把紧邻 `@` 前的疾病标题带入 LLM 证据窗口；该上下文只用于查缺补漏，不改变离线结果的最终门禁。
- LLM 新增关系在进入级联合并前增加关系类型触发词校验，避免仅凭实体共现生成“相关（导致）”等泛关系；标准骨性关节炎句真实调用后保留 5 条标注关系，未产生抽取错误。
- 服务器运行态已备份到 backups/task2_offline_route_opt_20260807_r1/。MCP 实际验证通过：标准 CMeIE 句离线保留 4 条关系；否定句不生成关系；任务二默认 hybrid 以 `dry_run=false`、`persist=false`、`refresh_analytics=false` 实际处理 1 条记录，未写入知识图谱、未刷新分析库且无抽取错误。

## 本轮任务二级联性能与分段归属复核（2026-08-09）

- 运行态继续使用 CBLUE CMeEE-V2/CMeIE 开发集前 500 条作为同批对照样本；该样本用于工程迭代和 PPT 展示，不替代完整开发集或官方测试集成绩。
- 离线与 hybrid 的首轮实体、关系抽取逻辑保持一致；hybrid 采用记录级缺口批处理、线程复用的 HTTP 会话、候选 ID 记录隔离和最多 200 条候选复核上限。模型请求默认 45 秒超时、4096 个输出 token 上限，模型失败时保留离线结果并记录错误。
- 对包含 `###` 分段标题的 CMeIE 文本，LLM 缺口关系新增最近疾病标题归属校验，防止后续疾病分段的症状、检查或用药事实归给前一疾病；该规则为项目内实现，并新增任务二回归测试。
- 当前服务器验证未写入知识图谱：CMeEE 500 条实体识别 offline/hybrid 的 P/R/F1 为 52.32%/29.23%/37.51% 与 51.71%/33.23%/40.46%；CMeIE 500 条关系抽取为 71.63%/6.90%/12.59% 与 70.59%/7.38%/13.37%。混合链的召回和 F1 提升，精确率仍受 CMeIE 未完整标注的语义关系影响，报告中不得表述为三项指标均超过离线。
- 随后使用相同口径跑完整开发集（CMeEE 5000 条、CMeIE 3585 条）：CMeEE offline/hybrid 的 P/R/F1 为 53.32%/27.50%/36.29% 与 53.24%/27.84%/36.56%；CMeIE 为 78.17%/7.49%/13.67% 与 77.79%/7.56%/13.78%。两项任务的 Recall 与 F1 均提高，Precision 分别基本持平和小幅下降；两次 hybrid 全量运行均无 LLM 请求错误，结果仍未写入知识图谱或刷新分析库。

- 知识库用于疾病背景、解释和来源证据，SQLite 分析库用于数量、排名、筛选、对比和图表。两类证据在 Agent 提示规则中明确分开，未把向量检索结果当作结构化统计结果。
- 任务三 NL2SQL 的稳定语义模板、模型兜底、只读执行与评测器均为项目内独立实现。评测方法参考 Spider/BIRD 的执行结果一致性思路，未使用或复制其数据集和官方评测代码。
- 评测同时报告有序结果、重复行保持结果和去重集合结果；正式准确率采用重复行保持的执行一致率。测试集设计基线与后续规则迭代回归分开记录，避免把已查看失败题型后的回归结果描述为独立泛化成绩。

## 本轮任务二 hybrid 正式留出集回归（2026-08-09）

- 评测数据仍来自 CBLUE 官方开发集：CMeEE-V2 dev 共 5,000 条，固定留出后评测 2,500 条；CMeIE dev 共 3,585 条，固定留出后评测 1,793 条。CMeEE 按位置、类型、文本严格匹配实体；CMeIE 按主语、关系、宾语严格匹配关系。
- 本轮未复制 CBLUE、DeepSeek 或其他外部项目代码；仅使用 CBLUE 数据格式与指标口径，并通过项目自身的 core/task2_verifier.py 完成缺口候选的类型和上下文门禁。
- 服务器真实 API 回归结果（未写入知识图谱、未刷新分析库）：CMeEE offline/hybrid 的 P/R/F1 为 53.94%/28.97%/37.70% 与 53.90%/29.94%/38.50%；CMeIE 为 78.67%/7.58%/13.82% 与 78.69%/7.73%/14.07%。混合链两项任务的 Recall 与 F1 均提升；CMeEE Precision 轻微下降 0.04 个百分点，CMeIE Precision 提升 0.03 个百分点。
- hybrid 的真实耗时为 CMeEE 211.28 秒、CMeIE 350.89 秒；吞吐分别为 11.83 条/秒和 5.11 条/秒。该吞吐包含 DeepSeek 模型调用，不能与不调用外部模型的 offline 吞吐直接作为同一成本口径比较。
- 结果与 PPT 表格、图表保存在 tmp/task2_optimization/r26_holdout_assets/；本轮新增的模型候选门禁只拒绝测量指标、裸设备缩写和泛化治疗短语等高风险补漏，不改变 CMeIE 数据、外部服务或知识图谱结构。

## 本轮任务二可靠性路由修正（2026-08-09）

- 本轮继续使用 CBLUE CMeEE/CMeIE 开发集的数据格式和严格匹配口径，未复制外部模型或评测实现，也未新增外部依赖。
- 可靠性路由改为高、中可靠离线事实直接保留；低可靠关系只有分组校准精确率不低于 55% 且原文存在对应触发词时才进入模型复核，避免把历史精确率接近随机的句内共现和上下文规则重新放回结果。低可靠实体进入受限复核，用于恢复被离线门禁过滤的正确部位等实体。
- LLM 缺口候选先执行项目内的位置、类型、否定、端点和关系证据校验；置信度不低于 0.90 的安全实体类型以及明确的“临床表现、发病部位”关系可直接合并，其余候选继续复核。批量复核按记录轮转并优先关系，仍保留 256 条总上限。
- 对 `疾病@正文` 中“部位（如……）”和“病因（如……）”的明确枚举增加项目内离线规则，标记为中可靠；该规则只连接已经在对应原文范围内识别的实体，未知术语仍由 LLM 补漏。
- 服务器真实 API 的同批 100 条 CMeIE 小样本最终结果为：offline P/R/F1 88.89%/10.39%/18.60%，hybrid 88.37%/12.34%/21.65%；混合新增 7 条关系，其中 6 条严格命中。该小样本只用于本轮工程验证，不替代 r26 固定留出集正式结果。
- 标准骨性关节炎记录含 5 条标注关系：最终离线规则返回 4 条，hybrid 在保留 4 条离线结果的基础上补出“病因→结晶性关节病”，得到 5/5；验证过程未写入知识图谱、未刷新分析库。
