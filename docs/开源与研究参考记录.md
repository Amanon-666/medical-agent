# 开源与研究参考记录

本文统一记录 MediFlow 在平台接入、数据处理、知识图谱、评测与可视化设计中实际采用或明确参考的外部来源。记录用于技术溯源和许可证核查，不表示将外部项目源码直接并入本项目。

## 记录规则

- **直接依赖**：运行时实际安装并调用的软件包。
- **API 接入**：仅通过公开接口调用外部服务，不复制其实现代码。
- **数据来源**：用于构建、验证或评测的数据集。
- **方法参考**：用于确定指标、接口或架构，不复制源码。
- **待选型**：已进入设计比较，但尚未成为当前实现。

如引入或修改外部代码，必须补充具体版本、文件范围、许可证和修改说明。

## 当前任务三实现的来源边界

任务三的语义层、只读 SQL 安全校验、分析记录、图表数据契约和报告导出为项目内实现：

- 数据库访问使用 Python 标准库 `sqlite3` 的只读能力；
- 当前网页统计图使用项目自有 SVG 渲染器，支持条形图、柱状图、
  环形图和折线图；
- 导出报告使用项目自有 HTML、CSS、CSV 和 JSON 生成逻辑；
- 当前实现没有复制 Apache ECharts、Vega-Lite、Spider 或 BIRD 的源码。

图表选择策略参考 Vega-Lite 的“数据字段与视觉编码匹配”思路，
但图表契约、选择规则和渲染代码均为项目内实现。下列项目没有成为
运行时依赖，不能描述为已集成组件。

## 本轮任务二级联实现记录

- CBLUE 的 CMeEE/CMeIE 数据仍只作为离线词典、关系词表和评测口径来源；本轮未复制 CBLUE 模型代码，也未把官方 test 集当作已获得标签的本地评测集。
- 离线词典构建规则增加了 HTML 标记过滤，并清理 `entity_lexicon.json` 中由 CBLUE 标注残留产生的 336 条 `<sub>/<sup>` 等标记词条；数据来源和许可证边界未改变，未复制外部代码。
- QASystemOnMedicalKG 仍作为医疗实体/关系数据和问题分类方法参考；本轮没有引入 Neo4j，也没有复制其问答代码。
- 新增的 `core/task2_cascade.py`、`core/task2_verifier.py` 和相关 schema 为项目内独立实现：LLM 只接收缺口句子或低可靠候选，输出经项目内文本存在性、类型、端点和复核门控后才进入结果；未复制外部实现代码。
- 本轮级联批处理修复为项目内编排调整：缺口候选与离线候选进入同一复核队列，候选 ID 按记录隔离，未新增外部依赖或复制外部代码。

## 本轮语义增强回归记录
- 本轮仅调整项目内的实体匹配、关系规则、缺口判断和 LLM 复核提示词，未引入外部代码或新依赖。
- 修复了嵌套词重复、知识库类型冲突、部分关系误判为已覆盖、实体否决连带删除关系以及新增关系计数重复统计。
- 实际 MCP 回归使用 CMeIE 标注句返回 5 条目标关系，包括缺口补出的“骨性关节炎→病因→结晶性关节病”；未写入知识图谱。

## 本轮离线关系规则与级联路由优化

- 本轮仍只使用项目现有的 CBLUE 词典、关系词表和知识图谱资产，未引入外部代码、模型或新的数据来源。
- 离线后端与 hybrid 首轮统一使用同一套实体、关系和候选路由逻辑：否定判断提前于已知关系匹配；关系使用实体实际位置；普通“在”不再直接触发发病部位；诊断上下文不再跨句补关系。
- hybrid 只复核中可靠离线候选；低可靠候选保留审计信息并计入“未送复核”，缺口句仍交给 LLM 查缺补漏；候选在复核前按语义去重。
- 服务器运行态已备份到 backups/task2_offline_route_opt_20260807_r1/。MCP 实际验证通过：标准 CMeIE 句离线保留 4 条关系；否定句不生成关系；任务二默认 hybrid 以 `dry_run=false`、`persist=false`、`refresh_analytics=false` 实际处理 1 条记录，未写入知识图谱、未刷新分析库且无抽取错误。

## 本轮 Nexent 知识库与任务三评测优化（2026-08-09）

- Nexent 2.1.0 继续作为 Agent 编排与本地知识库检索平台；任务二、任务三通过其原生 `knowledge_base_search` 工具绑定项目已有 `ccf_medical_kb`。本轮只调用公开 HTTP 接口和部署版数据模型，未复制或修改 Nexent 源码；Nexent 仓库许可证仍按 Apache-2.0 核查。
- 知识库用于疾病背景、解释和来源证据，SQLite 分析库用于数量、排名、筛选、对比和图表。两类证据在 Agent 提示规则中明确分开，未把向量检索结果当作结构化统计结果。
- 任务三 NL2SQL 的稳定语义模板、模型兜底、只读执行与评测器均为项目内独立实现。评测方法参考 Spider/BIRD 的执行结果一致性思路，未使用或复制其数据集和官方评测代码。
- 评测同时报告有序结果、重复行保持结果和去重集合结果；正式准确率采用重复行保持的执行一致率。冻结测试首次运行与后续规则迭代回归分开记录，避免把已查看测试失败后的回归结果描述为盲测成绩。
