# 任务三 PPT 展示文案

## 封面定位语

> **图谱驱动的自然语言分析：从医学知识查询到受控数据洞察**

一句话：用户用中文提问，系统理解意图 → 查询医学知识图谱 → 安全执行分析 → 输出答案、图表和报告。

---

## 第一层：问题理解 —— "听懂用户在问什么"

```
用户自然语言问题
        ↓
医学语义规划器（Medical Semantic Planner）
        ↓
同时识别三件事：
  ├─ 疾病实体："肺炎""糖尿病"（从数据库实时匹配）
  ├─ 分析意图：查症状？统计排名？对比分析？
  └─ 聚合需求：计数？分组？排序？Top-K？
```

**关键设计**：不是简单的关键词匹配。常见问题走确定性语义模板（9 类预定义医学事实），长尾表达交给大模型按受限 Schema 生成查询计划。两者结果合并去重——兼顾速度与覆盖面。

**PPT 配图建议**：一句话 → 拆成三个标签（疾病/意图/聚合）的示意图。

---

## 第二层：查询规划 —— "决定怎么查"

```
                查询规划器（Query Planner）
               /          |          \
              ↓           ↓           ↓
        知识图谱查询     SQL 分析    混合分析（规划中）
        (KG Query)    (NL2SQL)    (KG→SQL Hybrid)

查关系：             查统计：          先查 KG 拿中间结果
"肺炎有哪些症状"     "哪个科室疾病最多"  再喂给 SQL 做二次统计
   ↓                    ↓                  ↓
知识图谱              task3_analytics    "知识驱动的分析"
直接返回关系           .db 执行 SQL        （P1 规划中）
```

**关键设计**：
- **KG 查询**：直接从 44 万条医学三元组中检索疾病-症状/药物/科室等关系
- **NL2SQL**：大模型根据数据库 Schema 生成 SQL，经过三层安全校验后才执行
- **混合查询**（路线图）：KG 确定"分析哪些实体"，SQL 完成聚合统计——实现真正的知识驱动分析

**PPT 配图建议**：三条路径分叉示意图，标注各自的适用场景。

## 第三层：安全执行 —— "确保不会出错"

```
生成的 SQL
        ↓
┌─────────────────────────────┐
│ 第一道：语法校验             │
│ 只允许 SELECT / WITH 单条语句 │
│ 拒绝 DELETE/DROP/INSERT 等   │
├─────────────────────────────┤
│ 第二道：对象校验             │
│ 表名必须在 17 张白名单中     │
│ 拒绝系统表访问和自定义函数   │
├─────────────────────────────┤
│ 第三道：连接层隔离           │
│ SQLite 只读模式打开          │
│ PRAGMA query_only = ON       │
│ 即使前两道被绕过，引擎也拒绝写│
├─────────────────────────────┤
│ 资源限制                     │
│ 最多返回 200 行              │
│ 单次查询 5 秒超时            │
│ 每次分析最多 4 项查询        │
└─────────────────────────────┘
        ↓
  安全执行，返回结果
```

**一句话**：即使大模型"幻觉"生成了恶意 SQL，三层防线也能确保数据库不被修改。

**PPT 配图建议**：四道关卡纵向流程图，每道标一个锁的图标。

## 答辩要点备忘

**Q: 任务三和普通 NL2SQL 有什么不同？**
A: 做了三件事：(1) 医学语义层预判意图，常见问题不走模型，稳定且快；(2) 三层 SQL 安全防线，不是简单的前缀检查；(3) 查询结果结构化封装为分析对象，驱动统一的回答/图表/导出流程。

**Q: 为什么需要独立的分析库，而不是直接查知识图谱？**
A: 图谱库负责规范化事实和溯源证据，是关系型存储；分析库存储面向统计查询优化的关系视图，降低 NL2SQL 的 Schema 复杂度，保证 BI 查询性能。

**Q: NL2SQL 准确率怎么测的？**
A: 基于 task3_analytics.db 构建了 133 道冻结测试题，每道都有 Gold SQL 和 Gold Result。评测只看执行结果是否一致（Execution Accuracy），不比较 SQL 字符串。模板查询和自由 NL2SQL 分开统计。
